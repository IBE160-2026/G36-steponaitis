## Smart Warehouse Planner (G36)

Course project (IBE160) for warehouse location planning. Backend FastAPI + SQLAlchemy/Alembic on Python 3.12 managed by uv (`backend/`); frontend Next.js 16 + React 19 in an npm workspace (`frontend/`). Planning artifacts live in `.docs/planning-artifacts/`, stories and sprint status in `.docs/implementation-artifacts/`.

## Policy

- Never commit real company data or the old company Excel files; use only synthetic data from `data/sample/` (generated by `data/generate_demo_data.py`). `data/private/` is git-ignored and stays unused.
- Do not edit `data/answer-key/` or `data/sample/` by hand; regenerate samples with `uv run --with pandas --with openpyxl python data/generate_demo_data.py` from the repo root.
- Default git branch is `main`, never `master`.

## Where things are

- Backend app entry: `backend/swp/main.py` (`swp.main:app`); CLI `backend/swp/cli.py`. Layers `api > app > store > domain`, enforced by `backend/.importlinter`.
- Frontend app: `frontend/app/`; unit tests `frontend/tests/`; e2e specs `frontend/e2e/`.
- `frontend/AGENTS.md` is regenerated by `next dev`; read it before writing Next.js code and commit it unchanged.

## Running and verifying

Run every command from the repo root. Required: Node 24.x, Python 3.12, uv.

- Install: `npm install` (its `postinstall` runs `uv sync --directory backend --locked`).
- Dev: `npm run dev` (backend on 127.0.0.1:8000, frontend on localhost:3000 proxying `/api/*`). Single side: `npm run dev:backend` / `npm run dev:frontend`.
- Lint: `npm run lint:py` (ruff), `uv run --directory backend --locked ruff format --check`, `npm run lint:imports` (import-linter layer contracts), `npm run lint` (ESLint, frontend), `npm run typecheck` (tsc).
- Test: `npm test` (runs `npm run test:py` = pytest, then `npm run test:web` = Vitest).
- Traceability: `npm run trace` (SM-7) lists every core FR and NFR with the test names carrying its ID and fails when a core FR has none. Name new tests with their IDs (`test_fr17_…`, `it("fr21_…")`, e2e titles `uj1 …`).
- E2E gate (local): `npm run e2e` runs chromium, firefox and msedge; all three must pass with 0 failed, 0 flaky, 0 skipped. Install once with `npx --workspace frontend playwright install chromium firefox`; Edge is the installed Microsoft Edge (macOS Edge gets `--disable-gpu` from the config). `npm run e2e -- --project=chromium` is what CI runs. Playwright builds and starts the production app itself (`npm run e2e:serve`: `next build` + `next start`, backend with 4 uvicorn workers) against `backend/var/e2e.db`, which `e2e:reset-db` deletes on every server start; it reuses a running server on :3000 outside CI, so only one run at a time.
- `npm run e2e:production` runs the production-mode journey (APP_ENV=production, demo on); it never reuses a server, so port 3000 must be free.
- Run Python tools through uv (`uv run --directory backend --locked <tool>`), never bare `pytest`/`ruff`, which run outside the locked environment.

## Conventions that differ from defaults

- `swp.domain` imports only stdlib and pydantic; only `swp.store` imports SQLAlchemy/Alembic; `swp.api` never imports `swp.store` directly. When adding a dependency, add its top-level module to the `domain-pure` contract in `backend/.importlinter`.
- Build features as isolated vertical slices; put shared code in common folders rather than duplicating it.
- Launcher (flow map drawer) actions are data: add one by appending to `LAUNCHER_ACTIONS` in `frontend/lib/launcher/index.ts`; it gets only `LauncherContext` (plan id, `PlanSummary`, `send`, `navigate`, `notify`), so widen that type rather than editing the drawer.

## Story workflow rules

- A story with an acceptance criterion only a human can check (phone scan, eye check of print, someone else running the README) stays in `review` until the author confirms it in a session log; never set it to `done` before.
- A spec with `followup_review_recommended: true` blocks the next story until that follow-up review has run or the author waives it.
- Build sub-agents never start dev servers on ports 3000 or 8000 while an e2e gate is pending; the orchestrating session runs the gate.
- Before building a story, read deferred findings addressed to it in earlier specs and the open points in `.logs/<user>/issues.md` that name it.
- Run each epic's retrospective before the first story of the next epic.
