### Diff-scope review (bmad-review: adversarial, edge-case, verification-gap)

`bmad-review` ran in a subagent on `git diff 6f8e996^..dc41cf7 -- backend frontend`, without the generated `schema.ts`, with the three lenses in parallel. The lenses were weighted toward the story boundaries. Each finding below was re-checked against HEAD. Four candidates were dropped as unverifiable or needing hand-edited state.

- **R1 (medium, 4.2 → 4.3). The preview and the command can disagree across versions.**
  - `app/commands.py:57-66` stores `base_version` but never compares it. `manual-move-dialog.tsx:349-352` sends only `{part, from, to}`.
  - If another writer changes the plan between preview and confirm, the server applies the move to the current state. It may then combine or remove a move that the dialog showed as new.
  - This follows AD-6 ("`base_version` recorded, not enforced", `epics.md:165`; `ARCHITECTURE-SPINE.md:130`), and FR-41 is the planned warning.
  - I confirmed live that a `manual_move` sent with `base_version: 1` at version 3 applied as `moves_combined`.
  - Disposition: **defer to FR-41**, with a decision for Justas (action item 7).
- **R2 (medium, 4.3/4.4). The From choices are frozen when the dialog opens.**
  - `manual-move-dialog.tsx:302`: `const [choices] = useState(() => fromChoices(detail))`.
  - After a 409, or a move by another writer, the refetched detail never reaches the From select. The dialog stays on "{part} has no stock at {from}" until it is closed.
  - Disposition: **fix now** (action item 1).
- **R3 (medium, verification gap). Nothing tests the dialog's 409 path after an allowed preview.**
  - `manual-move-dialog.tsx:349-363` has no test. `tests/manual-move.test.tsx` covers only the pure helpers, and a grep for `409` and `command_rejected` in `frontend/e2e` finds nothing.
  - This is the path that exposes R2.
  - Disposition: **fix now** (action item 1).
- **R4 (medium, verification gap). No test checks the summary's `empty_best_locations` after a move.**
  - The summary reads `planning_copy` (`app/plans.py:137`), but every `empty_best_locations` assertion uses a state with no steps (`tests/app/test_plan_summary.py:55,177`).
  - `test_views_follow_planning_copy_api.py:48-60` checks the other views after a move, but not the summary.
  - Disposition: **fix now** (action item 2).
- **R5 (low). The Postgres `55P03` → 503 path is dead code.**
  - `store/plans.py:200` uses `.with_for_update()` with no `nowait`, and nothing sets `lock_timeout`. So Postgres waits instead of raising 55P03, and the `PlanBusy` docstring's 503 claim does not hold.
  - This was already recorded as a residual risk (`spec-4-2:184`, `issues.md:106`).
  - Disposition: **fix now** (action item 3).
- **R6 (low). Any Inventory part can be moved, even one with no analysis entry.**
  - `_refusal` (`planning.py:437-451`) checks stock but not `listed_parts`.
  - `build_part_detail` gives 404 for such a part, yet `before_after.py:114-120` lists it in moved in/out. This is reachable only through the API.
  - Disposition: **fix now** (action item 4).
- **R7 (low, 4.5 → 4.6). `has_moves` is "any effective move", not "anything differs".**
  - `before_after.py:164`: `has_moves=len(result.moves) > 0`.
  - Once epic 5 adds rounds, a move reversed in a later round keeps two effective moves while all counts are equal, and the "no moves" note is hidden.

  - The `moves_combined` toast leaves out the part number (:104).

  Disposition: **fix now** (action item 6).

  - Disposition: **defer**. It was recorded as a residual risk (`spec-4-3:192`), and the answer-key and sample sizes are small.

  - Disposition: **accept**. The schedule is bounded, and this is the intended answer to epic 3 R1.
