### Diff-scope review (bmad-review: adversarial, edge-case, verification-gap)

Review scope: `8cdc6b7^..4f15702`, with emphasis on story boundaries. The 2.3 shared facts and DataTable are reused by 2.4-2.6, and 2.6 wires the panel and search into the 2.3-2.5 pages.

**R1. Changing the aisle on Locations clears the Occupancy and Best filters.** All three lenses found this independently.
- `frontend/modules/locations/locations-page.tsx:165-170` resets the filters to `{...NO_FILTERS, aisle}` whenever `urlKey` changes.
- `changeAisle` (`:175-178`) calls `onAisleChange`, which runs `router.replace(… { aisle, part })` (`:256-258`). That changes `urlKey`, so the reset runs.
- The result: a planner presses "Empty", picks another aisle, and silently gets every location in that aisle.
- The reset was added by a Story 2.4 review patch ("the resync now resets to `{ ...NO_FILTERS, aisle }`", `spec-2-4-…md` triage). A fix for a hand-typed URL regressed the in-page path.
- `frontend/e2e/locations-table.spec.ts:55-72` picks the aisle before pressing Empty, so the failing order is never tested.

Disposition: **fix now**, with a test for the "filter, then change aisle" order.

**R2. DataTable keyboard open ignores interactive children, and Enter-to-open is untested** (adversarial + verification-gap).
- `onClick` skips targets inside `a, button, …` (`frontend/components/common/data-table.tsx:111-114`). `onKeyDown` has no such guard (`:120-128`), so Enter on a button inside a row with `onOpen` would open the row instead. This is dormant today: Parts rows have no interactive children, and Pick groups has no `onOpen`.
- No test presses Enter on a row, or opens a row while a user sort is active. The only test is the pure `nextRowIndex` (`frontend/tests/parts.test.tsx:149-159`), and the e2e clicks rows on unsorted tables (`frontend/e2e/part-panel-search.spec.ts:99`). A regression from `shown[index]` to `rows[index]` would open the wrong part after a sort, and no test would fail.

Disposition: **fix now**.

**R3. Stale search results look current** (adversarial + edge-case).
- `usePlanSearch` uses `placeholderData: keepPreviousData` (`frontend/lib/api/plans.ts:118-128`), but `search-field.tsx:189-198` never checks `isPlaceholderData`.
- While the next query loads, the old results stay clickable, and the no-match text names the old query.
- The 2.6 triage rejected this because it lasts one sub-second request.

Disposition: **defer**. Group it with the per-keystroke requests (no debounce, `issues.md:91`).

**R4. The panel and search wait forever on `plan_not_found`** (edge-case).
- If the plan is deleted mid-session, `part-panel.tsx:196-203` stays on "Loading part…" and `search-field.tsx:199-205` stays on "Searching…".
- There is no delete before Epic 6 (Story 6.4).

Disposition: **defer** to Story 6.4.

**R5. Focus and history edge cases of the PartPanel** (adversarial + edge-case).
- When the panel was opened from a deep link, or removed by browser Back, `close` or unmount leaves focus on `<body>` (`part-panel.tsx:61-67`). The 2.6 triage rejected the deep-link case.
- Opening part B while A is open pushes a new history entry (`:51-57`).
- `?loc=` and `?part=` together give two competing focus effects.
- Following the same `?loc=` link again neither refocuses nor resets filters, because `focusKey` is handled once per value (`data-table.tsx:95-98`).
- `?loc=` without a matching `?aisle=` marks the key handled while the row is hidden (`data-table.tsx:96-98`).

Disposition: **defer**. Pick these up with Epic 10, when chips point to the wall and focus routing changes.

**R6. DataTable roving tab stop.**
- The active row is stored by index, so after a sort or filter it points at a different row (`data-table.tsx:81,87`). The 2.3 triage rejected this as cosmetic.
- On Pick groups, each `PartCell` button is its own tab stop, so a table of N groups has 2N+1 tab stops (`pick-groups-page.tsx:33-40`). UX-DR18 says the table is one tab stop.

Disposition: **defer**. This is accessibility debt and should be reviewed before the Story 5.8 gate.

**R7. Occupancy percent rounds to 100.0 or 0.0 at the extremes** (edge-case).
- `occupied_percent` rounds half-up (`backend/swp/domain/views/locations.py:49-54`). 1,999 of 2,000 shows "100.0% occupied" while the counts say one location is empty.
- The counts are always shown beside the percent, which satisfies NFR-10.

Disposition: **defer**.

**R8. Smaller items.** Disposition: **defer** for all.
- The kernel holds the wire type `LocationRef` with `is_best=False` hard-coded (`backend/swp/domain/planning.py:106-127`). Epic 3 must edit the kernel by design (epic context: "Epic 3 fills `is_best`").
- `q` has no `max_length` (`backend/swp/api/routers/search.py:15`). The 2.6 triage rejected this.
- The client sort comment says "code-point order", but JavaScript `<` compares UTF-16 code units, which differ only outside the BMP (`frontend/lib/sort/index.ts:8-13`).
- The 400 px panel has no narrow-screen layout (`part-panel.tsx:172`; `issues.md:90`).
- A part number of `.` or `..` would be normalised away by `fetch` (`frontend/lib/api/plans.ts:104-105`). This is synthetic data only.
- The SearchField has no ARIA combobox and no arrow keys (`search-field.tsx:167-187`). UX-DR25 does not require them, and results are reachable with Tab.

The verification-gap lens found no backend gaps. Classify, pick groups, ordering, the shared facts and all four views are pinned against the answer key, including the 4400 equal-stock tie and the traps. CI runs pytest on SQLite and Postgres 17, plus Playwright Chromium.
