## Intent

**Problem:** Best-location marks already have a stored shape in `PlanState.best_marks`, but nothing decides which locations they make best: `location_ref` hard-codes `is_best=False`, and neither the plan summary nor the overview shows best or empty-best counts. Every count and every later rule (Epic 5) needs one shared answer.

**Approach:** Add the shared facts `covering_marks` and `is_best` (plus `best_counts`) to the domain kernel `domain/planning.py`, make the marks a value set in `PlanState`, wire `is_best` into every `LocationRef`, list covering marks per row in the locations view, add best / empty-best counts to the plan summary, and show those two counts on the Overview page.

## Boundaries & Constraints

**Always:** Marks are values (`{kind:"aisle", aisle}`, `{kind:"level", level, aisle|null}`, `{kind:"location", location}`), never indexes; duplicate marks collapse to one (first occurrence kept, stored order otherwise preserved). `covering_marks`/`is_best`/`best_counts` exist only in `domain/planning.py`; views import them. Aisle and level match by exact string equality with `LocationData.aisle` / `LocationData.level`. The domain stays pure (stdlib + pydantic). Marks never change `ImportData` or the planning copy's locations/inventory. Every test names its FR (SM-7). UI copy in English, glossary term "best location".

**Never:** No command types, command endpoint, events or `recent_commands` handling (Story 3.2). No client command flow (3.3) and no Best locations step UI or marking controls (3.4). No `schema_version` bump (the stored shape is unchanged). The frontend never computes best status or counts. No new domain slice module (the facts are kernel).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Aisle mark | marks `[aisle A]`, location in aisle A | `covering_marks` = `[aisle A]`, best | none |
| Level in all aisles | `[level 1, aisle null]`, locations with level `1` in any aisle | all of them best; level `2` not best | none |
| Level in one aisle | `[level 1, aisle B]` | level 1 in B best; level 1 in A not best | none |
| Single location | `[location A-01-01-03]` | only that code best | none |
| Overlap | `[aisle A, level 1 null]`; remove `aisle A` | A level-1 location stays best via the level mark; A level-2 location no longer best | none |
| Unknown target | `[aisle Z]` or `[location X-99]` not in import | nothing best, counts 0 | none (no error) |
| Duplicate marks | state JSON with `[aisle A, aisle A]` | validated `best_marks` == `[aisle A]` | none |
| Answer key | `data/answer-key/` with `best_location_marks` `[aisle A]` | 9 best, 1 empty best (`A-01-01-03`), nothing else best | none |

## Design Notes

`covering_marks` takes the planning copy first, like its kernel siblings (`aisle_of(copy, location)`, `stock_at(copy, part, location)`), because a location code alone does not carry its aisle and level; the story's `covering_marks(location, marks)` names the same fact. Golden shape:

```python
def covering_marks(copy, location, marks):
    loc = copy.locations.get(location)
    if loc is None: return []
    return [m for m in marks if (m.kind == "aisle" and m.aisle == loc.aisle)
            or (m.kind == "level" and m.level == loc.level and m.aisle in (None, loc.aisle))
            or (m.kind == "location" and m.location == location)]
```

Empty best = best and `is_empty(copy, code)` (zero-stock rows count as empty, so `A-01-01-03` is empty).
