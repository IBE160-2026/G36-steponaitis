The findings:

- **R1. MEDIUM: after any undo, the flow bar shows Recommendations as done (7.3 vs the Story 5 check rule).**
  - **Where:** `views/summary.py:110` computes the check as `latest_run(state) is not None and not open_recommendations(state)`. Undo (`history.py:36-57`) outdates every open recommendation of the latest run.
  - **Effect:** after run, apply, undo, the step reads "done" while the undo toast says "Run recommendations to continue", and Apply all is disabled.
  - **Inconsistency:** a kept open recommendation deliberately leaves the step unchecked (`test_fr7_recommendations_unchecked_while_kept_open_left`), but a run that undo has outdated becomes "done".
  - Reproduced in a scratchpad probe.
  - Disposition: **fix now** (action item 1). Also update the check rule in EXPERIENCE.md.
- **R2. MEDIUM: the toast's Undo is silently lost while another command is saving (7.3 vs the command client).**
  - **Where:** `sendUndo` (`lib/commands/undo.ts:28-38`) ignores the `busy` outcome. The client returns `busy` with no notice (`lib/commands/client.ts:137`). The toast is dismissed in `finally` whatever the outcome (`components/common/toast.tsx:80-85`).
  - **Why only the toast:** the header, panel and launcher Undo controls are disabled through `savingReason`. The toast action bypasses that check. `manual-move-dialog.tsx:356` does handle `busy`.
  - Found by reading.
  - Disposition: **fix now** (action item 2).
- **R3. LOW: a move toast's Undo stays live after a Run started from the page, and it outdates the whole new run (7.3).**
  - **Where:** the page's `run()` (`recommendations-page.tsx:616-630`) only announces. It never toasts, so the earlier apply toast with Undo stays on screen.
  - **Effect:** clicking it undoes the step and outdates every recommendation of the new round, under a toast that names round 1.
  - **Already triaged in part:** spec-7-3:177 rejected this as a wording issue only. The triage did not weigh that the toast stays clickable.
  - Disposition: **fix now** (action item 2).
- **R4. LOW (re-raise): a stale Undo prepared before a reset hits a reused move number (7.3 vs 7.4).**
  - **Where:** `undo` checks only `expected_move_number` (`history.py:72`), and reset sets `next_move_number` back to 1 (`:101`). `base_version` is stored but never compared (`app/commands.py`). The behavior check also saw a `run` with a stale `base_version` accepted with 200.
  - Reproduced in a scratchpad probe.
  - **Status:** spec-7-4:154 rejected it as AD-6 / Epic 15.
  - Disposition: **defer** to a decision (action item 8).
- **R5. LOW: No space rows still say "no free location" after an undo frees one.**
  - **Where:** `recommendations.py:613-636,697` reads the stored `latest.no_space`, which has no stale state.
  - **Scope:** this is not specific to epic 7. The same gap follows manual moves and mark changes.
  - Disposition: **defer**.
