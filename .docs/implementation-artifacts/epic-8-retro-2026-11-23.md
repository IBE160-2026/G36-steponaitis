### Diff-scope review (bmad-review: adversarial, edge-case, verification-gap)

`bmad-review` ran headless in a subagent over `git diff 31e7568^..a453a2b` (without `.docs/` and `.logs/`), with each lens in its own subagent. **R1. A command landing during a Print refetch can print the old list (medium).** `frontend/modules/move-list/move-list-page.tsx:60-72`.
- A confirmed command invalidates every active plan query (`frontend/lib/commands/client.ts:219-221`, `invalidateQueries` with its default `cancelRefetch`). That cancels the in-flight Print refetch.
- The cancelled refetch resolves with the current, old result (`isSuccess` true, old `dataUpdatedAt`). `committed()` then sees data "at least that fresh" and calls `window.print()` at once, with the old generated time and the old moves.
- This sits on the 8.3 boundary: the print flow meets the command-refetch path. The reviewer did not reproduce it at runtime; it needs a command to land during the refetch (another tab, or autosave).
- Disposition: fix (action item 2).

**R2. Two printouts within one minute have identical headers (medium, spec-level).** `frontend/lib/copy/index.ts:389` → `formatDateTime` (`frontend/lib/format/index.ts:55-57`) prints `HH:MM`.
- The spec makes the generated time "the only thing that tells two printouts apart", but also fixes it to `HH:MM`. "Print, fix a move, print again" inside one minute gives two identical headers. `view.version` is in the payload (`move_list.py:62`) but never printed.
- The code follows the spec, so the defect is in the spec. Disposition: spec reconciliation (action item 4).

**R3. Menu print (Ctrl/Cmd+P) skips the refetch (medium per reviewer).** `move-list-page.tsx:76-91`. This is the same item 8.4 deferred (A5). Disposition: defer; record it in AD-17 (action item 4).

**R4. A swap line has never been printed (medium, partly verified).** `move-list-page.tsx:101-104,135-136`.
- From, To and the "A ↔ B" line are `whitespace-nowrap` in the code font, and Note has `min-w-24`. The A4 print width is about 703 px.
- The 8.4 print e2e uses sample data with no swaps, so the 8.2 swap cell has never been laid out on paper. Whether it overflows is the reviewer's estimate and was not measured.
- This sits on the 8.2/8.4 boundary. Disposition: fix the verification gap (action item 3).

**R5. A failed first load of the print page is untested (medium, partly verified).** `move-list-page.tsx:234-258` (`errorMountedAt` and `loadError`).
- No unit test renders `MoveListPage`, and the e2e fails only the Print refetch.
- A regression could leave the page on "Opening the plan…" forever, or show an old error from an earlier visit.
- Disposition: fix (action item 3).

**R6. Pagination rules are checked only as computed CSS (medium).** `frontend/e2e/move-list-print.spec.ts:44-150`. The PDF read in Behavior verification confirms the repeated header and the page numbers in Chromium. Firefox pagination is unchecked. This is the same item as A5's band rule.
