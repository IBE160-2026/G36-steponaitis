### Diff-scope review (bmad-review)

**R1. Medium: the occupied dialog offers a Swap that the server always rejects when the dragged part is also stored at the target (12.1 vs 12.3).**
- Where: `frontend/modules/locations/drag/occupied-dialog.tsx:194-195`, commit `090fdf9`.
  - `useCheckedParts([dragged])` checks the dragged part on the "move" side.
  - `useCheckedParts(targetParts.map(...))` checks every target part on the "back" side, including the dragged part.
  - A one-part target has no checkbox, so its part is always the back choice (`:38-40`).
  - `swapReason` (`:49-57`) compares only counts, never overlap.
- What happens: the server refuses with "{part} cannot move both ways." (`backend/swp/domain/drag.py:81-84`). `sendFromDialog` closes the dialog on the refusal (`drag-context.tsx:212-215`).
- Consequence: when the target's only part is the dragged part, Swap can never succeed from the dialog, although it looks enabled. FR-33 allows one part in several locations, so this is an ordinary situation.
- Verification gap: `e2e/drag.spec.ts:511` avoids such targets on purpose, and the `uxdr10_`/`uxdr50_` Vitest cases use only lists that do not overlap. No story triage covered it.
- Disposition: fix now (action item 1).

**R2. Medium (verification gap): the NFR-8 "command plus the plan views < 1 s" check leaves out the wall, warehouse and move-list views.**
- Where: `backend/tests/app/test_nfr8_timing.py:25`. `VIEWS` holds `""`, `/parts`, `/locations`, `/pick-groups`, `/recommendations` and `/before-after`.
- Every drag uses the wall view, and Epic 12 changed the move-list builder (`_intact_swaps`). Neither is timed. The same file's AD-18 test already builds those URLs but checks only their size.
- Disposition: fix now (action item 2).

**R3. Low-medium: during a drag, every cell the pointer crosses requests a server preview, with no debounce.**
- Where: `drag-context.tsx:120-124`, from commit `6499d88`.
- Each preview replays the step log (`planning.py:655-662`). The cache only helps for cells already visited at the same version.
- This meets the AC's "at most once per target per version", but one sweep across a large aisle sends dozens of requests, and no timing test covers the preview.
- Disposition: fix now, with R2 (action item 2).

**R4. Low (verification gap): "at most once per target per plan version" is pinned only by the shape of the cache key.**
- Where: `frontend/tests/drag.test.tsx` `fr51_preview_key_includes_the_plan_version`. The e2e route on `**/moves/preview**` delays the reply but does not count requests.
- Removing `staleTime: Infinity` would break the 12.2 AC without any test failing.
- Disposition: fix now (action item 3).

**R5. Low: the Epic 12 e2e titles carry no FR IDs, so SM-7 under-reports FR-51's e2e coverage.**
- Where: `frontend/e2e/drag.spec.ts:40, 168, 273, 452, 491`. All five titles start `uj1 …` without `fr51`. `:491` also lacks `fr35`/`fr38`.
- `npm run trace` credits FR-51's e2e coverage to `user-journeys.spec.ts` only. Story 12.5 patched other titles for exactly this reason (AGENTS.md "Name new tests with their IDs").
- Disposition: fix now (action item 3).

**R6. Low: `drag.py`'s docstring says the drag check is "the same check" as Manual move, but it is not.**
- Where: `backend/swp/domain/drag.py:3-5`, `:38-44` and `:72-75`, against `planning.py:631-645`.
- The drag check also refuses a virtual or unknown from-location. Manual move checks only the to-location.
- No UI path reaches the difference, but the docstring hides it.
- Disposition: fix now as a wording change (action item 4).

**R7. Low (note only): the traceability scanner also counts `describe(` titles and commented calls.**
