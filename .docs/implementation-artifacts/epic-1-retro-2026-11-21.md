No such contract exists. Epic 1 has only one domain slice (`swp/domain/import_.py`) plus `views/summary.py`, so nothing is violated yet. Story 1.1's acceptance criteria do not require the contract.
Disposition: **fix now** (as spec reconciliation): add the contract with the first story that adds a second domain slice (Story 2.1).

**A2. Duplication map: no material duplication found.**

### Diff-scope review (bmad-review: adversarial, edge-case, verification-gap)

The review ran on `32a6df2^..6c83fab` without lockfiles, `schema.ts`, `.docs/` and `.logs/`, with emphasis on story boundaries. The findings below were re-checked against the source before routing.

**R1. One-group thousands separators are read as decimals** (adversarial + edge-case). `backend/swp/domain/import_.py:113,158-161`: `_PLAIN_NUMBER` is tested before `_THOUSANDS`. Re-checked: `_parse_number("1,234")` returns `1.234` and `"1.000"` returns `1.000`, while `"1,234,567"` and `"1 234"` are rejected. Story 1.5 AC rejects "a number with thousands separators". A one-group value is genuinely ambiguous because `,` is also an accepted decimal mark, and the 1.5 triage log rejected "`"1,234"` as decimal". The risk is a Quantity of 1,234 stored as 1.234 with no error. **Fix now**: reject the ambiguous `\d{1,3}[.,]\d{3}` form, or record the decision in the spec.

**R2. An out-of-range date crashes plan creation with 500** (edge-case). `backend/swp/domain/analysis.py:56-60`: re-checked, `period_for(date(1,1,15), 12)` raises `ValueError: year 0 is out of range`. A transactions file whose newest date is in year 1, or a typo far in the future, becomes `data_as_of`. The first case becomes `internal` instead of a file/row/column error. **Fix now**: bound parsed dates in `_parse_date` and report them as cell errors.

**R3. Client size pre-check and server body limit disagree near the limit** (adversarial + edge-case + verification-gap). `frontend/modules/new-plan/selection.ts:40` allows `total <= maxBytes` on file bytes only. `backend/swp/api/upload_limit.py:27-47` counts the whole multipart body against the same number. `frontend/tests/new-plan.test.tsx:111-113` locks in the client side. Files within a few hundred bytes of 4 MB pass the browser check and get a 413. **Fix now**.

**R4. A non-UUID plan id shows a raw Pydantic message with no way out** (adversarial + edge-case). `backend/swp/api/routers/plans.py:65-67` types `plan_id: uuid.UUID`, so `/plans/<typo>/overview` gets 422 `validation_failed`. `frontend/components/common/plan-status.tsx` then shows the message, and the shared hook (`frontend/lib/api/query-errors.ts`) redirects only on `plan_not_found`. The 1.9 triage rejected related rows ("placeholder bad-id feedback", "`/plans/new/<x>` parse"). **Fix now**: map an unparsable id to `plan_not_found`.

**R5. The start page `/` is a dead end when `GET /api/plans` fails** (adversarial + edge-case). `frontend/app/page.tsx:30` shows the error text. Queries never retry (`frontend/app/providers.tsx:15`), and the page offers no retry and no New Plan link. **Fix now**.

**R6. Story 1.4 test deferrals were not picked up by Story 1.8** (verification-gap). The 1.4 spec deferred tests for toast pause on hover/focus and Input Esc to Story 1.8 (`spec-1-4-…md:138-139`). Spec 1.8 reports "Deferred: none" and added neither: the only toast assertions are visibility checks (`frontend/e2e/new-plan.spec.ts:70`, `frontend/e2e/plan-overview.spec.ts:152-154`), and no test in `frontend/tests` or `frontend/e2e` presses Escape on an Input. The same gap applies to two review patches: Escape on the plan plate tooltip (`frontend/components/common/app-shell/plan-plate.tsx:37-49`, 1.9) and abort-on-unmount during upload (`frontend/modules/new-plan/new-plan-page.tsx:69-77`, 1.8). `issues.md` still has these as open items. **Fix now** (tests), plus process lesson L2.

**R7. The ConfirmDialog test checks a constant only** (verification-gap). `frontend/tests/components.test.tsx:177-183`; the component has no consumer yet. **Defer** to the first story that opens a confirm dialog (Reset… or Delete…).

**R8. Cancel or navigate-away can still create a plan** (adversarial + edge-case). `frontend/modules/new-plan/upload.ts:93-96` and `new-plan-page.tsx:69-77,146-148`: the abort is client-side only. Once the body is fully sent, the server commits, the UI reports "cancelled", and `PLANS_KEY` is not invalidated. Related: the Next rewrite proxy timeout (`frontend/next.config.ts:6`) could report a failure while the backend commits. **Defer**; demo-sized imports run in about 1.1 s (behavior check).

**R9. The error panel keeps errors for a replaced file** (edge-case). `frontend/modules/new-plan/new-plan-page.tsx:125-129`: `choose` clears the tile state and field errors but not the `role="alert"` panel, which stays until the next submit. **Defer** (cosmetic; UX-DR19/20 only require that the failing tile can be re-chosen).

**R10. Import edge cases recorded as residual risks in 1.5** (adversarial + edge-case). Three are already in `issues.md`: more than 10,000 blank rows gives the "more than N rows" message (`backend/swp/app/imports/readers.py:74-75`); cells over 1,000 characters are cut without an error, including identifiers (`readers.py:51-52`); and columns after 100 are cut. New from the review: a duplicated optional column (Warehouse) silently uses the first one (`import_.py:258-262`), and a numeric xlsx `7` vs CSV `"007"` canonicalize differently across files (`import_.py:134-144`). **Defer**, all synthetic-data-only for this project (`no-company-data` rule).

**R11. Smaller items.** **Defer** all:
- Every summary GET loads and validates the whole import JSON to compute two counts (`backend/swp/app/plans.py:99-119`).
- No maximum length on the plan name (`app/plans.py:42-49`).
- `plan_not_found` always says "This plan was deleted." even for an id that never existed (`frontend/lib/api/query-errors.ts:6`).
- `assert import_row is not None` guards integrity on read (`backend/swp/store/plans.py:90`).
